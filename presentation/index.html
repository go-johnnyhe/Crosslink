Implementation & Methodology

Stack

  • Next.js route handlers for the API
  • React client, no external state library
  • One in-memory store for all rooms

Synchronization

  • Client requests GET /api/rooms/:code every 850ms
  • Server re-validates every move on arrival
  • Plain HTTP polling, no WebSocket connection

Testing & User Manual

Automated

Manual

Improvements & Future Work

  • Persistent storage across server restarts
  • WebSocket-based sync instead of polling

Conclusion

TIC//LINK implements every required feature: matchmaking, synchronized moves, chat, win/loss/draw tracking, and a connection activity log. Game state lives in memory and resets when the server restarts — a deliberate simplification for this project's scope.
